# The resource-erasure surface: what the act does with every carrier a resource reaches.
#
# Under goal "A single resource can be erased out of a live estate" (spec: temper-artifacts
# specs/2026-09-28-resource-erasure-design.md, D9). Sibling of scripts/personal-data-surface.txt and
# scripts/sensitivity-scan-surface.txt.
#
# WHY THIS FILE EXISTS.
#
# The erasure act (`_resource_erasure_apply_redaction`, D2) names the columns it empties by hand. The
# first draft of that list missed `kb_chunks.header_path` and `kb_citation_audits.reason`: both were
# prose, both were reachable from the resource, and nothing said so until a joint read with the
# sensitivity sweep. This file is where that question is answered for every such column, and
# resource_erasure_surface_test.rs fails until it is.
#
# THE INVARIANT. Every CARRIER in a table a resource reaches has a line here: handled by a numbered
# D2 step, or out-of-scope with its reason. A carrier is (ruled 2026-10-02):
#
#   * a column sensitivity-scan-surface.txt classes `scan` (authored text), or
#   * a column personal-data-surface.txt classes `content`, `incidental` or `derived` (jsonb, bytea,
#     vector and search-index columns that hold or are computed from what someone wrote).
#
# NOTHING HERE DECIDES WHAT A COLUMN HOLDS. Those two manifests are the definitions; this file only
# says what the act does about the columns they mark. A third classification would drift.
#
# NOTHING HERE LISTS TABLES. Reach is derived from the live catalog by the test (ruled 2026-10-02,
# amended 2026-10-03):
#
#   roots  kb_resources, kb_content_blocks, kb_chunks, kb_block_revisions, kb_edges.
#   edges  a foreign key makes its table a child of the table it references. A single-column CHECK
#          on a `*_table` discriminator makes its table a child of each table it names: a
#          polymorphic reference, which carries no foreign key.
#   walk   every child of a reached table, recursively, the ledger included. A table reached only
#          through a foreign key into kb_events is reached all the same: that is how
#          kb_contexts.telos_centroid, which is computed from a context's goal resources, comes into
#          view. Its lines say when the event key is the only path.
#
# Every base-table `*_table` column must carry a CHECK that enumerates the tables it may name
# (`col IN ('kb_a', 'kb_b')` or `col = 'kb_a'`), or the test fails: a discriminator the walk cannot
# read could point at a resource unseen.
#
# STEP NUMBERS are the spec's D2 numbering (1–9, 7a). The function's own section labels count
# differently; read the spec, not the comment, to check a line.
#
# WHAT THIS FENCE DOES NOT SEE, STATED SO NOBODY INFERS COVERAGE FROM SILENCE.
#   * Rows. A line is checked at column grain: the D2 function has a statement that writes the column
#     with an erasure value (a constant, or an 'erased…' literal joined to an id). Which rows that
#     statement reaches is the act's own witnesses' job. Where a handled column keeps rows tied to R
#     that the act leaves, the line's note says so. The check reads statements, not control flow:
#     an UPDATE under a branch never taken, after a RETURN, or with a WHERE that matches nothing
#     still binds.
#   * Derivation without reference. A vector computed from R's content is tied to R by no key: a
#     region's centroid (a mean over its members) and a context's telos_centroid (a mean over its
#     goals). The walk reaches both tables by other paths, so both have lines, but nothing structural
#     would find the next such aggregate. Both are handled by step 6.
#   * References with neither a foreign key nor a CHECKed `*_table` discriminator:
#     - kb_remote_sources, referenced by kb_block_provenance through (source_kind, source_id). Its
#       `uri` is declared below because D2 step 9 does reach it; the test binds that line to the
#       function body instead of to the walk.
#     - discriminators spelled `*_kind` (kb_block_provenance.source_kind,
#       kb_citation_audits.source_kind). Both tables are reached through block_id.
#     - bare uuid references: kb_idempotency_keys.resource_id, and kb_cogmap_components.member_ids
#       (a uuid[] of members). Neither holds a carrier today.
#   * Columns neither sibling manifest classes as a carrier: an `identifier` or `reference`, a
#     `structural` text column, and any type both manifests leave out (text[], json, enums).
#   * Schemas other than `public`. sensitivity.findings points at resources (target_table,
#     target_id, resource_id) without a key. It holds no authored text. Every digest the sweep
#     stores is keyed by a salt that never enters the database: a finding's match fingerprints
#     (sweep D11) and content_hash, the memo's hash of each unit a detector found nothing in, and
#     place_observations' last hash of a mutable place. For a place the act reached (and one the
#     block history scrub or the principal act emptied), the sweep drops the finding's digests and
#     the memo rows carrying its hash 30 days after it first sees the finding closed (migration
#     20261004000010). Every memo row goes 30 days after it was written, and every observation of
#     an erased resource on the next expiry call, and no hash column keeps planner statistics
#     (migration 20261007000010). The category, detector and match count, which say what kind of
#     data R held, stay as the record of what was found. The act itself never names the schema.
#
# FORMAT (line-oriented; `#` comments and blank lines ignored)
#   [tables]                                  section marker; cut 2 adds [payload] (D9's payload half)
#   <table>.<column> | <disposition> | <note>
#
# disposition
#   handled:D2.<step>     the D2 step that empties or sentinels the column. The test checks that the
#                         live `_resource_erasure_apply_redaction` assigns it, in an UPDATE of its
#                         table, an erasure value: NULL, '', '{}' or '"erased"' (optionally cast), or
#                         an 'erased…' literal joined by || to an id.
#   repointed:D2.<step>:<table>.<column>
#                         the rows citing it are re-pointed, through the named column, to a sentinel
#                         row, and the original is deleted when nothing else cites it. The test checks
#                         for a re-point that assigns something other than the column's own value, and
#                         for the DELETE: statements, not the rows they reach.
#   out-of-scope          the act deliberately leaves it; the reason in the note is REQUIRED.

[tables]
