# CLI Reference (Source Notes)

> This file is **out-of-source documentation** about how the installed
> `reference.md` is produced. It is not read by the CLI at runtime.
>
> The installed `reference.md` skill file is **generated dynamically** from
> the clap command tree by `temper skill generate` / `temper skill install`.
> Both the command-table and the footer (resource types, stages, orientation
> projection, context-requirement matrix, etc.) live in
> [`src/commands/skill.rs`](../src/commands/skill.rs) as the
> `generate_reference()` function and the `REFERENCE_FOOTER` constant. Edit
> that file to change the installed reference.
>
> Because the command table is generated by walking `Cli::command()`, every
> resolvable clap subcommand appears automatically — including `resource facet`
> and `cogmap materialize`. There is no static per-command list in this
> repository to fall out of sync; a grep of this file for a verb will find
> nothing even though the *installed* reference lists it. Grep `temper skill
> generate`'s output (or the installed reference.md under your skill directory)
> to check whether a command is actually documented.

## Static skill-content files (sources of truth)

The default install directory is `~/.agents/skills/temper` (the vendor-neutral `agents`
target); `--target claude` / `--target opencode` install into that agent's config home
instead. Paths below are shown for the default.

| File | Source |
|------|--------|
| `SKILL.md` | `crates/temper-cli/templates/skill.md` (askama) |
| `reference.md` | generated by `skill.rs` (`generate_reference`, `REFERENCE_FOOTER`) |
| `session-lifecycle.md`, `outcome-registers.md`, `working-a-goal.md`, `data-artifacts.md` | `templates/shared/` (rendered per surface) |
| `implementation-grounding.md`, `cognitive-maps.md`, `teams.md`, `querying.md`, `project-setup.md`, `admin.md` | this directory |
| `memories.md` | `memories-cli.md` here (CLI) or `mcp/memories.md` (MCP) |
| `knowledge-base.md` | `skills/temper-knowledge-base/knowledge-base.md` (hand-written) |

Files earlier releases shipped and this one retired (`workflows/*.md`, `subagent-guidance.md`,
`plan-verification.md`, `review-gates.md`, `session-wrap.md`) are removed from an install by
`RETIRED_SKILL_FILES` in `skill.rs` when their bytes match a shipped revision.

## Invocation rule (preserved here for human reference)

**Always run `temper` directly from PATH.** Never use `cargo run -p
temper-cli`, `python`, full paths, or any indirect invocation method — even
when working inside the temper source repository. The installed binary may
differ from the in-development code, and that is intentional: we use the
installed CLI to manage our own workflow while evolving the crate.

Before running any temper command, verify the binary exists with `which
temper`. If it is not on PATH, install it with `cargo install --path
crates/temper-cli --locked` or ensure `~/.cargo/bin` is in your PATH.

## Skill-only commands

These are handled by the skill routing layer (the SKILL.md template), not the
`temper` CLI directly. They compose multiple CLI commands into guided
workflows:

| Skill Command | What It Does |
|---------------|-------------|
| `task start <slug>` | Shows task, moves to in-progress |
| `task resume <slug>` | Shows task, reads last session's Next Steps |
| `task create` | Guided interactive task creation with prompts |
| `session start` | Start a session without a predefined task |
